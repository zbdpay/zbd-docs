## Description

Defines a new virtual currency for your publisher account. Once players hold a
balance in a currency, its `code` can no longer change, so decide on it before
you start crediting.

`precision` is **required** and may be `0`. Omitting it returns a `400` — it
does not fall back to a default. A currency with `precision: 0` has no
sub-units, so amounts are whole numbers of that currency.

## Configuration

### Header Parameters

<ParamField required header="x-api-key" type="string">
  Your ZBD publisher API key. Call this from your server only.
</ParamField>

### Path Parameters

<ParamField required path="publisherId" type="string">
  Your ZBD publisher ID.
</ParamField>

### Body

<ParamField required body="code" type="string">
  Short ticker for the currency. Must match `^[A-Z0-9]{2,4}$`. Immutable after creation.
</ParamField>

<ParamField required body="name" type="string">
  Display name, up to 100 characters.
</ParamField>

<ParamField required body="precision" type="integer">
  Number of decimal places the currency is denominated in. May be `0`. Omitting this is a `400`.
</ParamField>

<ParamField body="icon_url" type="string">
  URL of an icon to display alongside the currency.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST https://api.zbdpay.com/api/v1/publishers/{publisherId}/virtual-currencies \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "GOLD",
    "name": "Gold Coins",
    "icon_url": "https://cdn.zbdpay.com/virtual-currencies/gold.png",
    "precision": 0
  }'
```
</RequestExample>

Every other endpoint addresses this currency by its `code`, not the returned `id`.

## Errors

| Status | Reason |
|---|---|
| `400` | `precision` omitted, `code` fails `^[A-Z0-9]{2,4}$`, or `name` exceeds 100 characters |
| `401` | Missing or invalid API key |
| `403` | The API key does not belong to `publisherId` |
