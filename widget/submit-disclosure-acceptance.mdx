---
title: "Submit Disclosure Acceptance"
description: "Record disclosure acceptance for a widget user."
api: "POST https://api.zbdpay.com/api/v1/widget/users/{userId}/disclosures"
---

## Description

Records the user's acceptance of the latest version of each disclosure type in `acceptedDisclosureTypeIds`.

For widget ACH cashout, present the Electronic Funds Transfer disclosure and
submit type `6`, as shown below. Types `1` through `5` are not required for widget
eligibility. Do not call this endpoint from a browser, mobile client, game
client, or WebView.

## Configuration

### Header Parameters

<ParamField required header="apikey" type="string">
  Your ZBD project API key.
</ParamField>

<ParamField initialValue="application/json" header="Content-Type" type="string">
  Content Type
</ParamField>

### Path Parameters

<ParamField required path="userId" type="string">
  The ZBD user ID returned when the widget user is created or resolved.
</ParamField>

### Body Parameters

<ParamField required body="acceptedDisclosureTypeIds" type="array">
  Disclosure type IDs accepted by the user. For widget ACH cashout, send `[6]`. ZBD records acceptance for the latest version of each submitted type.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST https://api.zbdpay.com/api/v1/widget/users/{userId}/disclosures \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "acceptedDisclosureTypeIds": [6]
  }'
```
</RequestExample>

<ResponseExample>
```json 201
{
  "success": true,
  "message": "Publisher user disclosure agreements recorded successfully.",
  "data": {
    "acceptedDisclosureTypeIds": [6]
  },
  "error": null
}
```
</ResponseExample>

## Disclosure Type IDs

| Disclosure type | Type ID |
|---|---:|
| Electronic Funds Transfer | `6` |

Disclosure types `1` through `5` can appear in disclosure status responses, but
they are not widget session or ACH cashout prerequisites.

## Existing Users

If an existing user has not accepted the current Electronic Funds Transfer disclosure, call this endpoint with type `6`. Do not rely on an idempotent user-create call to update disclosure acceptance.

## Errors

| Status | Reason |
|---|---|
| `400` | `acceptedDisclosureTypeIds` is empty, missing, or contains an unknown disclosure type |
| `401` | Missing or invalid API key |
| `403` | The API key is not allowed to access widget disclosure APIs |
| `404` | `userId` does not belong to the project associated with the API key |
