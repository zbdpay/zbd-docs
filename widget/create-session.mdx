## Description

Creates a type-4 Legacy Cashout Widget session. Returns a `session_token` (JWT)
and the `widget_url` to open in an iframe or WebView. The session is valid until
`expires_at`.

Supply exactly one of `email` or `access_token`. On the email path, an optional
`reference_id` validates that the email and publisher reference identify the
same project user. It is not a session ID. On the access-token path, identity
comes from the token, so omit `reference_id`.

<Info>
  This endpoint belongs to the Legacy Cashout Widget contract. EA integrations
  use [Create EA Session](/widget/create-ea-session) instead.
</Info>

The widget handles OTP email verification, identity verification (Onfido), bank linking (Plaid), and cashout initiation internally.

Widget session creation does not query or enforce disclosure acceptance. It can
report outstanding disclosures as a read-only status, but the widget does not
render documents or collect acceptance. Types `1` through `5` can be ignored for
widget eligibility.

ACH cashout submission is a separate gate. Before an ACH cashout can succeed,
your application must present and record the latest Electronic Funds Transfer
disclosure (type `6`). This requirement is enforced only when the ACH cashout is
submitted. See [Disclosure Agreements](/widget/disclosures).

## Configuration

### Header Parameters

<ParamField required header="apikey" type="string">
  Your ZBD project API key (production scope).
</ParamField>

<ParamField initialValue="application/json" header="Content-Type" type="string">
  Content Type
</ParamField>

### Body Parameters

<ParamField body="email" type="string">
  User's email address. Required when `access_token` is omitted; do not send both.
</ParamField>

<ParamField body="reference_id" type="string">
  Optional stable publisher user reference used to validate the email mapping.
  Use only with the email path.
</ParamField>

<ParamField body="metadata" type="object">
  Optional string key-value metadata to attach to the session.
</ParamField>

<ParamField body="access_token" type="string">
  Existing user access token. Required when `email` is omitted; do not send both.
  Identity comes from this token and OTP is skipped.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST https://api.zbdpay.com/api/v1/widget/users/session \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "player@example.com",
    "reference_id": "player-42",
    "metadata": { "source": "your-game" }
  }'
```
</RequestExample>

<ResponseExample>
```json 200
{
  "success": true,
  "data": {
    "session_token": "eyJhbGciOiJSUzI1NiIs...",
    "expires_at": "2026-06-01T00:00:00.000Z",
    "widget_url": "https://widget.zbd.gg?session_token=eyJhbGci..."
  }
}
```
</ResponseExample>

<Note>
  `webhook_url` is not a session field. Configure server webhooks for the
  publisher integration rather than sending a callback URL on each session.
</Note>
