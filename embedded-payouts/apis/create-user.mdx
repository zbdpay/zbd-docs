---
title: "Create a User"
description: "Create a user for your project."
api: "POST https://api.zbdpay.com/api/v1/widget/users"
---

Call this from your server. The call is idempotent when both `email` and `reference_id` match the same existing user, and that user is returned. If either one is already linked to a different user, the call returns `409` (`PA5004`).

## Configuration

### Header Parameters

<ParamField required header="apikey" type="string">
  Your ZBD project API key (production scope).
</ParamField>

<ParamField initialValue="application/json" header="Content-Type" type="string">
  Content Type
</ParamField>

### Body Parameters

<ParamField required body="reference_id" type="string">
  Your stable internal user identifier. Must be unique per project.
</ParamField>

<ParamField required body="email" type="string">
  The user's email address. ZBD uses it to send the user verification codes.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST https://api.zbdpay.com/api/v1/widget/users \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "reference_id": "player-42",
    "email": "player@example.com"
  }'
```
</RequestExample>

## Response

The response `data` includes the new or existing user, and an `outstanding_disclosures` array listing any disclosures the user hasn't accepted yet.

<ResponseField name="outstanding_disclosures" type="array">
  Disclosures the user hasn't accepted yet. Each entry includes `id`, `type_id`, `name`, `description`, `version`, `content_uri`, `created_at` and `due_date`.
</ResponseField>

## Errors

| Status | Meaning |
|---|---|
| `400` | Invalid `email` or `reference_id` |
| `401` | Missing or invalid API key |
| `403` | The project isn't enabled for this endpoint |
| `409` | The `email` or `reference_id` is already linked to a different user (`PA5004`) |
