Pay players out in real money: create payout users and sessions, fund and read balances, quote and submit cash outs, and configure webhooks.

## Base URL

```
https://api.zbdpay.com
```

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/v1/widget/users` | Create a cashout-widget user |
| `GET` | `/api/v1/widget/users/{userId}` | Read a widget user |
| `PATCH` | `/api/v1/widget/users/{userId}` | Update a widget user (email) |
| `POST` | `/api/v1/widget/users/session` | Mint an Embedded Payouts session — distinct from the Embedded Accounts `/zbd-widget/sessions` mint |
| `GET` | `/api/v1/widget/users/{userId}/balance` | USD-points balance |
| `GET` | `/api/v1/widget/users/{userId}/transactions` | USD-points history. **Not** the Embedded Accounts history route — do not confuse with `GET /api/v1/users/{userId}/transactions` |
| `POST` | `/api/v1/widget/users/fund` | Credit USD points to a widget user |
| `POST` | `/api/v1/widget/users/deplete` | Debit USD points from a widget user |
| `GET` | `/api/v1/widget/publishers/transactions` | Publisher-wide cashout-funding activity — the only publisher-wide feed that exists today |
| `GET` | `/api/v1/widget/cashout/cap-status` | Cashout headroom for the banner: `velocity_limits`, `rail`, `currency`, `window_months`, `min_amount_cents`, `rolling_12_month_total_cents`, `cap_cents`, `remaining_cents`, `state`, `upgraded_kyc_required`, `current_kyc_tier`, `as_of` |
| `POST` | `/api/v1/widget/cashout/preflight` | Quote FX + fees before submitting |
| `POST` | `/api/v1/widget/cashout` | Cashout to a linked bank account. Idempotency goes in the `idempotency_key` **body field** — the `Idempotency-Key` header is ignored |
| `POST` | `/api/v1/widget/cashout/giftcard` | Cashout as a Bitrefill gift card. Same body-field idempotency rule |
| `GET` | `/api/v1/widget/exchange-rate` | Approximate FX rate for gift-card display and affordability *(path disputed: changelog 8.93.0 gives the `/widget/` form, the integration draft gives `/api/v1/exchange-rate` — confirm before publishing)* |
| `POST` | `/sandbox/api/v1/widget/cashout` | Sandbox variant. The **request host** selects the policy, not the key — a sandbox host needs a sandbox-issued key |
| `POST` | `/api/v1/projects/{projectId}/webhooks` | Create a project webhook config |
| `GET` | `/api/v1/projects/{projectId}/webhooks` | List project webhook configs |
| `PUT` | `/api/v1/projects/{projectId}/webhooks/{id}` | Update a project webhook config |

## Conventions

- **Response envelope** is uniform: `{ success, message, data, error }`. The HTTP status line is authoritative and is deliberately not duplicated in the body. On success `error` is null; on failure `data` is null.
- **Amounts** are always integers in the currency's smallest indivisible unit (`int64`, min 1), at that currency's own `precision`. Balances come back the same way — never assume two decimals. `BTC`, `USD`, `EUR` and `USDZ` exist alongside publisher-defined currencies.
- **`Idempotency-Key`** (UUID header) is required on reward, spend and gift; a replay returns the original result and echoes `Idempotency-Replayed`. The cashout rails are the exception — body field, header ignored.
- **`x-workspace-id`** is optional and honoured on **reward and spend only**. A workspace that isn't yours returns 404 without transacting.
- **`X-Request-Id`** is accepted everywhere as a trace id.
- **Error prefixes:** `PA` accounts · `EG` economy · `ZWS` sessions · `AK` API keys · `CH` shared HTTP. Money-movement endpoints are the exception — their `error.code` carries a request trace id rather than a stable business code, so branch on the HTTP status and `error.message` there, and quote the trace id to support.
- **Rate limits** apply per credential. Sandbox is roughly 30× more generous than production, so a clean sandbox run does not characterise production — load test against realistic limits.

## Current limitations

- **No server-to-server balance read.** `account-summary` takes a player session token only. The one balance figure a publisher key ever sees is `user_spendable_balance` on the spend response.
- **No fiat purchase of virtual currency.** Bundles are readable; buying one is not implemented yet.
- **Cash out runs on Embedded Payouts.** The live rails move USD points through the Embedded Payouts surface rather than a publisher's own virtual currency.
